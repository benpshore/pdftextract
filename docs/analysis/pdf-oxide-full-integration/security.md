# PDF Oxide security and compliance adapter

This checkpoint integrates byte-oriented APIs from the registry crate `pdf_oxide = 0.3.78`, with default features disabled. It preserves each immutable source and returns separately named derivative artifacts. These operations must run through the bounded worker for untrusted documents. An in-process API call alone does not bound upstream allocations, recursion, CPU time or hidden I/O.

The module is `src/oxide/security.rs`; synthetic integration regressions are in `tests/oxide_security.rs`. The integration owner runs combined checks serially. Test outcomes must be appended after those commands execute; written tests are not execution evidence.

## Capability contract

| Operation | Supported request and output | Explicit limitations |
| --- | --- | --- |
| `security.inspect` | One PDF; encrypted/authentication state, nonsecret encryption dictionary fields, decoded permission flags and authenticated page count. | Does not expose `/O`, `/U`, `/OE`, `/UE` or key bytes. Missing/wrong passwords are inspection states; no unauthenticated page-count claim. Permission flags are reported, not enforced. |
| `security.encrypt` | `user_password`, `owner_password`, optional `algorithm: "aes256"`; AES-256 revision 6, `encrypted.pdf`. A full rewrite is followed by a bounded update of only `/Encrypt`, adding the pinned writer's missing mandatory `/Perms` block while preserving every existing ciphertext byte and the file key. Independent lopdf 0.45.0 checks authenticate user and owner roles separately, then load the actual serialized document with each password and verify page count before return. | New passwords travel only in the private worker request. Never put them in argv, logs or responses. Passwords must satisfy SASLprep and fit 127 UTF-8 bytes both before and after normalization; owner must remain nonempty. Empty user passwords are permitted. Legacy RC4/AES-128 writing is not enabled. Output permission flags are all allowed; this does not alter engine or platform security settings. Repair and serializer provenance are explicit in the result. |
| `security.decrypt` | Context password authenticates the PDF; full-rewrite `decrypted.pdf`. | Produces an explicitly unencrypted derivative; does not overwrite the encrypted source. Wrong/missing/unsupported encryption errors remain distinct at the context boundary. |
| `security.redact_text` | Nonempty `regions` array with one-based `page` and finite positive `[x0,y0,x1,y1]` in PDF user-space points; destructive text operator rewrite and `text-redacted.pdf`. | Text-only scope. Rejects encrypted sources, tagged documents, annotations, XObjects, inline images, marked content and unknown operators on target pages before producing a derivative. Does not promise removal of duplicate secrets elsewhere, metadata or font tables. Empty/nonintersecting rectangles cannot be mistaken for verified removal: reports include actual glyph counts and `global_secret_removal_verified: false`. |
| `security.sanitize` | Pinned catalog/Info sanitizer; `catalog-sanitized.pdf`, actual removal counts and scope. | Only catalog `/Metadata`, `/OpenAction`, `/AA`, `/Names/JavaScript`, `/Names/EmbeddedFiles` and trailer `/Info`. Page/field actions, annotation attachments, `/AF`, image metadata and OCGs are not comprehensively scrubbed. Shared attachment objects still referenced by a page annotation survive and are an intentional negative-control regression. Not a security sandbox. |
| `compliance.validate` | `standard`: eight PDF/A levels, PDF/UA-1/2, or ten PDF/X levels; errors/warnings with source locations and statistics. | Calls pinned validators and labels their verdict `upstream_is_compliant`. No independent standards certification, current-standard completeness or accessibility-quality guarantee. |
| `compliance.convert_pdf_a` | `standard`: supported PDF/A level; `pdfa-candidate.pdf`, conversion actions/errors, converter validation and a fresh unchanged validator report. | The pinned converter downgrades some missing-font errors. The fresh report retains validator findings. Font embedding, raster flattening and synthesized structure are disabled to avoid implicit host-font lookup or unbounded raster work. Encrypted sources must first become an explicitly decrypted derivative because the converter reopens source bytes without authentication. A candidate can remain nonconformant. |
| `signatures.inspect` | Bounded iterative AcroForm field walk, inherited `/FT`, claimed metadata and strictly typed ByteRange; no CMS/key output. Catalog signature-permission references are reported separately. | Uses a custom traversal because the upstream recursive enumerator has no cycle/depth guard. A range with four numbers is not automatically whole-file coverage. Reports `claimed_ranges_end_at_eof`, while `whole_document_coverage_verified` remains false because signature-gap binding is not verified. No certificate trust, revocation, timestamp or modification-permission assurance. |
| `signatures.verify` | Optional `pdf-oxide-signatures` feature; detached CMS cryptography and digest over the claimed byte ranges. | No signing, private keys, trust roots from files, TSA, OCSP, CRL fetch or network client. Only `adbe.pkcs7.detached` and `ETSI.CAdES.detached`. `valid_for_claimed_byte_ranges` does not assert signature-gap binding, signer identity, certificate-chain trust or absence of later modifications. Positive cryptographic qualification needs an approved signed fixture; malformed-CMS tests alone cannot establish it. |

All document operations require one input and a whole-document request. Page subsets must first become a separate explicit derivative. Every security derivative and PDF/A conversion rejects filled signature values before rewriting; the shared editor guard uses the same bounded check. Catalog `/Perms` references under `DocMDP`, `UR` and `UR3` also block rewriting even without an AcroForm. Missing or null `/V` on an unfilled signature field is permitted. This is a conservative preservation policy, including invalid/synthetic signatures: no implicit signature invalidation, signing or re-signing is authorized by a normal edit. No invalidation override is exposed.

The adapter enforces the shared input, output, page and item limits and refuses unknown JSON parameters. Fixed ceilings currently come from the root operation contract: 64 MiB total input and serialized output, 256 pages, 10,000 items. The signature walker adds a 64-level/reference-chain depth limit. Redaction preflight bounds aggregate decoded content bytes and operator count, and fails on damaged content-array members instead of accepting the upstream loader's skipped decode error. These post-decode bounds complement the worker memory/time budget; they do not prevent every allocation before the limit check.

## Test obligations

The synthetic suite exercises independent lopdf decrypt of AES-256 output, owner/user authentication, wrong/missing passwords, source identity, password non-disclosure, refusal of silently truncated passwords and unsupported legacy algorithms; targeted text removal from decoded objects with public-text controls; unsupported image/marked-content carriers and malformed arrays; catalog sanitization and shared attachment nonremoval; all 20 validator levels; PDF/A candidate fresh validation; unsigned/inherited signature fields, cycles, partial coverage, overflow/noninteger ranges and feature-specific malformed-CMS behavior; item/output/page-selection limits and unknown-path-parameter rejection.

The encryption interoperability controls include empty user passwords, normalized Unicode, prohibited characters, a normalized-empty owner password and normalization that expands beyond 127 bytes. The direct `stringprep = 0.1.5` dependency is the same locked version already used by both PDF libraries. Its validation prevents the pinned writer's fallback to unnormalized bytes or silent truncation. The independent loader must receive the password at load time: lopdf's unauthenticated load intentionally returns only the encryption dictionary, and later `decrypt()` does not reconstruct missing page objects. Its password-aware reader normalizes at authentication but passes raw input to key derivation; independent Unicode loads therefore receive explicit SASLprep bytes. The public `security.decrypt` operation is separately tested with the caller's original Unicode input and independent target/control text checks.

Remaining qualification includes positive approved detached-CMS fixtures, independent standards-validator evidence, image/path/Type3/OCG destructive redaction coverage, comprehensive active-content sanitization, and platform-specific subprocess containment. These remain explicit gaps, not green-smoke accuracy or security claims. No signing, certificate generation, private-key read, persistent server, network validation, publication or source overwrite is part of this module.

`tests/oxide_worker.rs` additionally exercises the shipped `tpe oxide` subprocess path: creation/query source provenance and installed limits, no-clobber publication, a bounded publisher failure, malformed/unknown/out-of-range requests, output overflow, private request/password-file channels, a 128 MiB decoded-comments fixture confined to a 32 MiB-growth worker, stopped-worker timeout/SIGINT/SIGTERM cleanup, full-stdout-pipe backpressure and inherited descriptor flags, and synthetic URI/Launch/JavaScript actions against an ephemeral loopback listener and disposable marker. Parent-side decompression-pressure construction streams fixed 64 KiB blocks into the compressor; it does not retain the decoded fixture. Every spawned controller has a kill/reap guard and an independent test deadline. Absence of side effects from the action fixture is not evidence of a general network/process sandbox.
